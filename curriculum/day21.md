# Day21：无提示迁移与系统路线图

> 状态：待实现
>
> 里程碑允许跨多个工作日

## 目标

验证用户能否使用自己的研究工作台处理一个未详细教学的候选，并决定系统下一阶段怎样迭代。重点是研究过程，不是一次闭卷答题或最终盈利数字。

## 候选生成

工作台从当前市场或机会雷达中推荐一个此前未深入研究的候选。用户在提交初步解释前只看到真实现象、交易证据、数据质量和产品背景，不显示 Agent 机制结论。

## 用户独立研究动作

1. 决定是否选择该候选，或说明另一个候选更值得研究；
2. 给出初步机制解释；
3. 查看竞争假设后，选择或质疑区分性实验；
4. 解读实验与纸上回放结果；
5. 说明结果支持什么、不能证明什么；
6. 决定继续采集、改进工具、扩展 venue、只做影子运行或停止该路线；
7. 指出工作台下一项最值得实现的能力。

Agent 负责运行与实现，不替用户做选择和结果解释。

## 最终成果

```text
持续运行的浏览器研究工作台
可复用 Python / CLI / Jupyter 工具
全量候选与双榜历史
用户初步解释、竞争假设与实验历史
可成交纸上回放与执行失败模型
实时影子研究
机会雷达与接入路线
下一阶段系统路线图
```

## 完成条件

- 候选和实验可以从保存数据重算；
- 用户在看 Agent 结论前完成初步解释；
- 实验真正区分竞争机制；
- 用户能解释结果分布与失败，而非只报最好值；
- 研究方法能迁移到新资产、venue 或机制；
- 系统仍可继续采集、研究和增加适配器；
- 用户知道 paper 结果没有证明未来盈利；
- 不自动获得真实下单权限。

## Day21 之后

根据实际研究价值决定：

- 扩大连续影子运行；
- 正式接入雷达中的新 venue/链上机制；
- 深化某个候选机制；
