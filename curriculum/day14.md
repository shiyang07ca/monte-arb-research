# Day14：研究工作台 v0

> 状态：重新设计完成，待实现与真实研究
>
> 里程碑允许跨多个工作日
>
> 用户时间：工作日 30–45 分钟；周末可深挖 1–2 小时

## 目标

把 Day12–14 已有的市场目录、经济映射和当前盘口能力，变成一个用户每天真正使用的浏览器研究工作台。旧的“时间字段课程页”降级为内部数据质量模块，不再作为 Day14 学习主体。

## 工作台新增能力

1. 自动扫描 Lighter–Hyperliquid 全部可映射永续；
2. 保存全部候选，不写死 WTI/Brent；
3. 分别生成交易吸引力榜与研究价值榜；
4. 每次优先展示最多 3 个不重复候选；不足 3 个时不凑数；
5. 单候选页先显示真实现象和证据，隐藏 Agent 机制解释；
6. 用户提交简短初步解释后，解锁竞争假设与实验建议；
7. 保存用户解释、Agent 假设、实验、结果和系统改进；
8. 现有时间、身份、映射和数据质量诊断作为候选证据展示。

## 初版候选检测器

- 跨场两种方向的可成交价差；
- funding 差异；
- mark/oracle/mid 与盘口关系异常；
- 深度与 spread 不对称；
- RWA session/roll/恢复附近异常；
- 时间错位、过期、缺口或身份异常。

检测器输出原值、基线和证据，不直接称为盈利机会。

## 双榜

### 交易吸引力

Day14 只显示当前可成交差、当前盘口深度、市场状态、映射证据和数据质量。持续时间与重复频率由 Day15 连续采集提供；多个规模、费用、funding 和退出成本由 Day16 提供。尚未实现的组成明确显示 `not_computed`，不提前排序。

### 研究价值

显示现象新颖度、竞争解释、实验信息增益、系统复用价值和跨市场迁移价值。

两个榜分别显示组成，不合成神秘总分。

## 用户研究动作

工作台给出最多 3 个真实候选后：

1. 用户选择一个；
2. 在看 Agent 分析前，给出简短初步解释，也可以说“不知道，先验证 X”；
3. 解锁后比较 Agent 的竞争假设；
4. 选择一个实验或指出实验设计问题；
5. Agent 实现并运行；
6. 用户解释结果意味着什么和下一步；
7. Agent 把结果实现成至少一项可复用改进。

不要求用户写代码，不用浅选择题或固定模板。

## 完成条件

### 系统

- 工作台作为单一持续应用实际运行；
- 自动扫描和全量候选可重算；
- 当前快照双榜与最多 3 个候选的推荐理由可解释；
- 候选页解锁流程、假设与实验记录可用；
- 实验结果能返回候选并生成系统改进任务；
- 没有 execution client 或真实订单路径。

### 学习

- 用户完成一次真实候选选择；
- 留下未被 Agent 锚定的初步解释；
- 选择/质疑一个区分性实验；
- 解释实际结果；
- 在后续新候选中再次使用至少一个 Day14 方法。

两组条件都满足才完成 Day14。当前旧版 HTML、REST 冒烟快照和测试通过不算 Day14 完成。
