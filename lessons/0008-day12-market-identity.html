关键代码 1

市场身份不是一个 ticker

@dataclass(frozen=True, order=True)
class MarketIdentity:
    venue: str
    product_type: str
    venue_namespace: str
    symbol: str
    local_id: str

你刚才说“需要 ticker 和 market_id 的映射关系”，方向正确。更精确地说，需要保存完整市场身份与本地编号的绑定。原因是相同 ticker 可能出现在不同场所、产品类型或命名空间中。

Lighter 返回两份没有 symbol 的盘口，程序应该怎样绑定？
选择一种方案，查看它能否阻止静默串市场。
关键代码 2

Hyperliquid 的两个数组必须先按原始位置配对

universe = response[0]["universe"]
contexts = response[1]

if len(universe) != len(contexts):
    raise SourceShapeError("meta/context length mismatch")

for index, (meta, context) in enumerate(zip(universe, contexts)):
    record = normalize(meta, context, index_in_meta=index)

如果只过滤 universe 中的下架市场，再与未过滤的 contexts 重新 zip，后面的市场都会拿到相邻市场的数据。这种错误尤其危险，因为价格仍可能看起来合理。

点击后比较“先过滤”和“先配对”的结果。

真实仓库操作

你可以直接重跑，而不是相信页面截图

  1. 在仓库根目录运行扫描命令： 
    PYTHONPATH=src python3 -m monte_arb.cli scan \
  --venue lighter \
  --venue hyperliquid:xyz \
  --inspect-book lighter/perp/default/WTI/145 \
  --inspect-book lighter/perp/default/BRENTOIL/159 \
  --inspect-book hyperliquid/perp/xyz/xyz:CL/110029 \
  --inspect-book hyperliquid/perp/xyz/xyz:BRENTOIL/110049 \
  --output research/runs/day12-scan.json
  2. 运行冻结响应测试：
    PYTHONPATH=src python3 -m unittest discover -s tests -v
  3. 查看结果：research/runs/day12-scan.json；查看请求与原始文件：research/manifests/day12-universe.json。
