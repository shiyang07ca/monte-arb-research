Day 7 · Data quality & reproducibility

让每个样本都能解释自己

今天的胜利不是得到更漂亮的统计，而是让你知道：一行数据从哪里来、是否完整、为什么能或不能进入统计。

研究任务：清洗 Lighter WTI（market_id=145）与 BRENTOIL（market_id=159）公开快照。

今天的唯一胜利

看到一个异常时，不先删它；先给它 UTC 时间、来源路径、原因码和统计准入状态。原始 JSON 永远不覆盖。

1. 清洗规则：保留、标记、准入分离

问题实际动作统计含义
timestamp统一为 UTC，保留 candle 毫秒 / funding 秒原值可回溯，不猜时区
重复 timestamp保留原 JSON，输出重复计数显式复核后再准入
缺失小时标记 gap不插值，不伪造交易时点
非法/非正价格保留原行和原因码排除对应价格统计
close 跳点 > 5%保留并加异常 flag不是自动删除理由
 
raw JSON
  → parse UTC + source path
  → quality flags
  → price / funding / combined admission
  → chronological train / validation / test

Primary source：Lighter candles API。文档说明单次最多返回 500 根 candle，且零值可能从响应中省略；所以“没有字段”不能直接变成 0。

4. 时间切分：不能让未来进入过去

train450 timestamps最早 60%
validation150 timestamps中间 20%
test150 timestamps最后 20%

切分按唯一 UTC timestamp 的时间顺序进行，不随机打乱。当前它只是研究纪律，不是策略回测结果。

5. 迁移验收

先关闭资料，凭理解回答，再点击检查。你的答案应体现“异常保留，状态明确”。

如果哪里不清楚，直接追问。今天的通过标准不是得到更好的收益，而是让第三方可以从 CSV 的 source path、timestamp 和原因码重建你的准入判断。
