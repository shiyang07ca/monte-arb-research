先审计数据，再谈 WTI–BRENTOIL 价差

今天只学一个可迁移的技能：拿到一批真实 API 响应时，你能判断“它是什么、覆盖了多久、有没有重复/缺失、两腿是否真的可比”，而不是被一个漂亮的相关系数带走。

建议用时：30 分钟核心 · 60 分钟复现 · 90 分钟反例　｜　研究对象：WTI market_id=145，BRENTOIL market_id=159

本课的红线
当前仓库的结论仍是 研究 Blocked、真实执行 No-Go。审计通过只代表“数据可以被诚实描述”，不代表策略成立。

1. 先建立文件地图

raw／原始响应lab/data/lighter_rwa_raw/
保留 API 返回的字段和原始时间；不可覆盖。
manifest／采集记录lighter_rwa_capture_manifest.json
记录端点、参数、HTTP 状态、接收时间和 SHA-256。
audit／审计摘要lighter_rwa_data_audit.json
覆盖、重复、描述性统计和阻断项；不是策略回测。
aligned／共同小时序列lighter_rwa_aligned_1h.jsonl
只保留两市场拥有相同 timestamp 的观察。

关键区别：common_rows=500 是“成功匹配到的共同观察数”，不是“有 500 个独立、充分、无缺陷的历史样本”。

2. 审计顺序：五个问题

  1. 身份：文件是不是目标市场？WTI 必须是 145，BRENTOIL 必须是 159。
  2. 时间：timestamp 的单位是什么？统一到 UTC 后，起止时间是什么？时间是否单调？
  3. 完整性：有多少行、多少唯一 timestamp、多少重复？小时桶是否缺失？
  4. 数值：OHLC 是否满足 high ≥ max(open, close)、low ≤ min(open, close)？价格和数量是否为正？
  5. 可比性：两腿是否处在同一个时间窗口、相同粒度、明确的价格语义和相同的清洗规则下？
主动回忆（先不要运行命令）
如果 WTI 与 BRENTOIL 各有 500 行 1h 数据，但其中一边少了 3 个小时桶，为什么不能直接把第 1 行和第 1 行相减？
提示：行号不是时间；比较必须依赖 timestamp。

3. 用真实仓库数据复现

先运行项目已有的只读审计脚本：

python3 lab/audit_lighter_rwa.py

再运行下面的最小复现，检查审计 JSON 是否能被你自己重新算出：

python3 - <<'PY'
import json, math, statistics
from pathlib import Path
rows = [json.loads(x) for x in Path(
    "lab/data/lighter_rwa_aligned_1h.jsonl"
).read_text().splitlines() if x.strip()]
w = [r["wti_close"] for r in rows]
b = [r["brentoil_close"] for r in rows]
wr = [math.log(w[i] / w[i-1]) for i in range(1, len(w))]
br = [math.log(b[i] / b[i-1]) for i in range(1, len(b))]
mx, my = statistics.mean(wr), statistics.mean(br)
cov = sum((x-mx)*(y-my) for x, y in zip(wr, br)) / (len(wr)-1)
print("common_rows =", len(rows))
print("return_rows =", len(wr))
print("correlation =", cov / (statistics.stdev(wr)*statistics.stdev(br)))
print("range_utc =", rows[0]["timestamp_utc"], "→", rows[-1]["timestamp_utc"])
PY

5. 一个字段，三个不能混淆的层次

层次例子审计问题
数据存在timestamp、c、v字段是否出现、能否解析、单位是什么？
数据可比WTI/BRENTOIL 同一 UTC 小时是否同粒度、同窗口、同价格语义？
数据可交易目标数量的 bid/ask 走档是否能开仓、持有、退出，并计算费用/funding/残余暴露？
注意：当前 orderBookDetails 只支持纸上检查市场规格和精度。它不是连续盘口历史，不能证明目标数量可以成交。
