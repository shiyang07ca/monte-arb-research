Lighter WTI/BRENTOIL 原始数据审计卡

目标不是找一个漂亮数字，而是知道这个数字能支持什么、不能支持什么。

一、文件与证据层次

文件作用不能替代
lighter_rwa_raw/*.jsonAPI 原始响应；保留字段和原始 timestamp。不能替代清洗记录。
lighter_rwa_capture_manifest.json端点、参数、HTTP 状态、接收时间、SHA-256。不能证明数据长期稳定。
lighter_rwa_data_audit.json覆盖、重复、描述性统计、阻断项。不能替代净 PnL 回放。
lighter_rwa_aligned_1h.jsonl按共同 timestamp 生成的双市场小时序列。不能证明两腿经济上可对冲。

二、审计五步

  1. 身份：WTI = 145；BRENTOIL = 159；确认 market_type=perp。
  2. 时间：识别毫秒/秒；转换 UTC；检查起止范围、单调性和时间桶间隔。
  3. 重复：按“市场 + timestamp”分组；报告重复行和重复 timestamp，不能静默覆盖。
  4. 缺失：用相邻 timestamp 检查缺小时；不插值；写入 missing_interval 状态。
  5. 数值：检查价格/数量为正；OHLC 约束；异常值保留原始记录并写原因码。

三、常见字段

字段含义（当前数据层）审计提醒
tcandle timestamp，当前 raw candle 为毫秒。不能和 funding 的秒级 timestamp 直接比较。
o/h/l/c开、高、低、收价格。不要把 candle close 自动叫 mark、index 或成交价。
v / V返回中的成交量字段。先确认单位和官方定义，再进入容量计算。
i原始响应中的附加标识字段。未经官方字段定义，不把它当 timestamp。
funding ratefunding 原始 rate。不能单独当成个人现金收益。
funding valuefunding 原始 value。必须核对方向、仓位数量、结算价格和账户账本。
directionfunding 返回的方向标签。不能仅凭方向标签推导你的仓位现金流。

六、不要犯的四个错误

  • 按数组下标匹配两腿，而不是按 timestamp。
  • 看到 duplicate 为 0，就声称数据完整。
  • 把高相关性写成协整、均值回归或盈利证据。
  • 把 funding API 字段直接相减，再把结果当成个人净现金。
