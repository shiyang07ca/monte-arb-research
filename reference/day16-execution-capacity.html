共同敞口、入场 VWAP 与往返基线

屏幕价差只是候选；完整判断至少需要共同数量、四次主动成交、费用、funding 与未来退出状态。

口径

字段公式/语义
共同经济敞口两腿 qty × multiplier 完全相等，并同时满足数量网格与最小单
入场可成交价差(卖腿 VWAP − 买腿 VWAP) / 参考价 × 1e4；只在目标共同敞口全成时输出
盘口冲击分解买/卖腿从 top-of-book 到 VWAP 的恶化；VWAP 已包含它，禁止重复扣除
冻结盘口往返入场两腿 + 同一敞口反向退出两腿；只是四次主动成交基线，不是未来退出预测
费后结果任一账户实际费率未知即 null；funding 无持有时间即 null

数量顺序

目标 USD / 两腿价格
→ 计算双方 exposure step = quantity_step × multiplier
→ 取双方 exposure step 的最小公倍数
→ 向下取最大共同经济敞口
→ 校验两边 min_base / min_quote
→ 两腿按对应 qty 逐档走 L2
→ 任一腿未全成：保留 unfilled 与 residual，目标规模 PnL = null

容量

最大测试档全成时显示 ≥ $X，只是容量下界。首次失败档单独记录；低于最小单的档位跳过。

真实 v2 结论

  • BRENTOIL 当前快照：小规模入场接近 0，$500/$1000 转负；同盘口往返全档为负。
  • AAPL / META / SPCX 某方向入场为正，但同盘口往返为负：正入场价差不是完整利润。
  • BOT 大规模部分成交时不发布目标规模 PnL，只保留成交率、未成交量与残余敞口。

刷新语义

GET  /workbench/api/execution          只读当前快照
POST /workbench/api/execution/compute  冻结盘口自定义规模重算
POST /workbench/api/refresh            仅 --live-refresh 模式真正重扫市场
全市场顺序扫描约 100 秒；capture_span_ms 必须可见

仍缺证据

  • Hyperliquid/Lighter 账户实际费率
  • 指定持有区间的 funding 现金流
  • 未来退出时的真实 L2
  • 账户可用保证金、权限和组合保证金状态
