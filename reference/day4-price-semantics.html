价格语义参考卡

一个 API 返回多个价格，不代表它们描述同一个过程。先决定研究问题，再选价格字段。

一、字段分工

字段它更适合回答不能直接当作
oracle_price外部价格源当前观察/输入是什么？你的成交价
index_price指数/基准价格机制如何定价？目标数量的成交价
mark_price保证金、清算和未实现 PnL 使用什么公平价格？可以立即实现的现金 PnL
candle_close某个固定时间窗口最后的聚合观察值是什么？该时刻一定能成交的价格
mid_price盘口中心在哪里？买入 ask 或卖出 bid
trade_price过去发生过一笔成交的价格是多少？未来仍有同样价格和数量
bid / ask此刻盘口最优买价/卖价在哪里？目标数量全部成交的平均价；还需深度

二、研究问题到价格

问题首选语义关键限制
马上买入ask，按目标数量走 ask 档必须检查深度、部分成交和延迟。
马上卖出bid，按目标数量走 bid 档必须检查深度、部分成交和延迟。
未实现 PnL/清算距离mark_price不是现金 PnL。
外部基准/价格输入oracle_price / index_price需要状态、新鲜度和公式语义。
历史小时收益candle_close必须保留时间戳和窗口定义。

三、RWA 定价转换：两组时间常数

这里不要把两个 τ 混成一个：第一组控制“价格来源的权重切换”，第二组控制“内部价格的 EMA 反应速度”。

阶段问题当前官方页面给出的 τ
来源权重切换oracle stale 后，多快从外部 oracle 转向内部价格？τ_mark = 1 min、τ_index = 1 min
内部 EMA 平滑impact price 进入内部价格后，多快跟随新订单簿信息？index τ = 30 min、mark τ = 2 min
 
外部 oracle（主要来源）
        │
        ├─ 正常：参与 index / mark 定价
        │
        └─ stale：oracle 权重下降，内部权重上升
                    ↓
             内部订单簿 impact price
                    ↓
               时间加权 EMA
                    ├─ index：τ = 30 min
                    └─ mark ：τ = 2 min

官方 RWA 定价文档说明：外部 oracle stale 时，机制逐步转向内部价格；外部价格恢复时，内部价格会即时向外部价格收敛。内部价格基于订单簿 impact price，并用时间加权 EMA 平滑。

w_oracle(t) = w_oracle(t−1) × exp(−Δt / τ_source)
w_internal(t) = 1 − w_oracle(t)

EMA_t = α × impact_t + (1 − α) × EMA_(t−1)
α = 1 − exp(−Δt / τ_ema)

τ_source 决定“信谁”，τ_ema 决定“内部价格反应多快”。它们都不是成交延迟或市场关闭时间。

五、最小 PnL 反例

entry = 75.00, quantity = 1
mark = 75.03, bid = 74.90, ask = 75.10

多头按 mark 的未实现 PnL： (75.03 − 75.00) × 1 = +$0.03
多头立即卖出的纸上 PnL：    (74.90 − 75.00) × 1 = −$0.10

两者不同不是矛盾：一个是 mark 估值，一个是按 bid 平仓的纸上可实现结果；还没有计入手续费、funding、滑点、深度和延迟。
