# Brent–WTI 相对价值研究模块 v1

Status: ready-for-human

## Problem Statement

现有工作台把内部 JSON 和逐规模计算结果直接铺到页面上，缺少日常研究任务所需的信息层次。用户无法快速判断数据是否可用、当前 Brent–WTI 关系相对历史是否异常、变化由哪条腿或哪种市场机制推动，以及指定规模的执行摩擦是否会吞掉观察到的偏离。

项目也把每日共学误做成页面表单。真正需要长期积累的是可复用数据集、采集脚本、分析模块、浏览器研究功能和清楚的心智模型，而不是要求用户提交低价值解释或完成固定学习动作。

## Solution

建立只读研究操作台，并先完成 Brent–WTI 相对价值专题模块。最小 Dashboard 展示模块入口和数据健康；油专题把 Lighter、Hyperliquid、Variational 导入数据和长期外部参考分为独立价格源，提供同步时间序列、原始美元价差、价格比值、对数比值、冻结对冲模型、参考残差、机制诊断和指定规模执行摩擦。

主页面不展示原始 JSON。原始和派生数据通过明确的下载接口与 CLI 提供。Variational 只读取 `monte-fox` 的脱敏市场观察，不读取账户、订单或执行状态；没有本地录制时明确显示不可用。

## User Stories

1. 作为研究者，我希望打开首页先看到各研究模块和数据健康，以便知道哪些内容可以使用。
2. 作为研究者，我希望首页突出 Brent–WTI 当前状态，以便一键进入当前主研究对象。
3. 作为研究者，我希望切换 Lighter、Hyperliquid、Variational 和长期外部参考，以便不混淆不同价格含义。
4. 作为研究者，我希望切换 24 小时、7 天、30 天、1 年和全部范围，以便比较短期变化与长期背景。
5. 作为研究者，我希望同时查看两腿价格、美元价差、比值、对数比值和参考残差，以便理解每个量回答的不同问题。
6. 作为研究者，我希望看到冻结模型的形成窗口、alpha、beta、中心和尺度，以便知道残差如何得到。
7. 作为研究者，我希望看到当前值在同一价格源自身历史中的位置，以便避免跨来源错误比较。
8. 作为研究者，我希望看到最近变化由 Brent 还是 WTI 主导，以便定位现象来源。
9. 作为研究者，我希望看到时段、展期和价格源分歧诊断，以便识别结构性变化或数据问题。
10. 作为研究者，我希望机制诊断列出证据和限制，而不是要求填写假设表单，以便把时间用于高质量研究。
11. 作为研究者，我希望选择方向和资金规模查看 Lighter/Hyperliquid 的冻结盘口进入成本、往返摩擦、成交率和未知费用，以便判断研究价值。
12. 作为研究者，我希望 Variational 以 RFQ 机制单独标识，以便不把 RFQ 当作可逐档行走的 L2。
13. 作为研究者，我希望缺少 Variational 登录录制时页面明确说明导入方法，以便不把缺失数据误解为零。
14. 作为研究者，我希望下载当前专题 JSON 和单个价格源 CSV，以便在 Python 或 Jupyter 中二次分析。
15. 作为研究者，我希望每个数据源显示最新时间、覆盖、样本数、缺口和错误，以便判断结论强度。
16. 作为维护者，我希望用一个 CLI 重新采集并生成专题数据集，以便页面和脚本使用同一份计算结果。
17. 作为维护者，我希望原始响应保存到 Git 外、派生数据集保存 schema 和来源元数据，以便重算和审计。
18. 作为维护者，我希望 HTTP 页面只消费稳定研究投影，以便以后替换前端而不改计算模块。
19. 作为维护者，我希望旧执行引擎作为内部计算模块继续复用，以便不重复实现 L2 走档。
20. 作为维护者，我希望 Dashboard、油专题、Funding、Execution 和数据目录职责分开，以便后续独立扩展。
21. 作为维护者，我希望工作台始终声明只读且没有执行客户端，以便不会从研究功能意外发送订单。
22. 作为学习者，我希望关键概念直接结合当前真实数据解释，以便形成可以迁移到其他相对价值策略的心智模型。

## Implementation Decisions

- 产品范围是只读研究操作台；不包含下单、仓位管理、真实 PnL 或自动执行。
- Dashboard 负责模块导航、摘要和数据健康；详细图表和验证进入专题页面。
- 第一专题是 Brent–WTI 跨标的相对价值，不把它与同标的跨场所价差混成一个指标。
- 价格源分别保存 Lighter K 线、Hyperliquid K 线、Variational 指数/RFQ 导入和长期外部参考；页面不跨来源计算未经声明的统一序列。
- 同步只接受相同时间桶；不使用未来值或隐式前值填补缺腿。
- 分析投影包含原始美元价差、比值、对数比值、冻结线性模型和参考残差。模型参数、形成窗口和限制随数据发布。
- 机制诊断使用确定性规则，至少覆盖当前偏离、24 小时腿贡献、场所分歧、UTC 时段代理，以及展期、funding、执行摩擦和数据健康的已知结果或证据缺口。
- Lighter 与 Hyperliquid 使用公开 K 线和冻结 L2；v1 执行表明确为 1:1 场所数量摩擦基线，不冒充 beta 对冲或策略 PnL；Variational 仅导入 `monte-fox` 的 `market_observation`，忽略账户、订单和执行事件。
- Variational 数据缺失时返回 `unavailable` 和原因，不生成示例值。
- HTTP 提供 Dashboard、油专题、数据目录、稳定 JSON 和 CSV；JSON 是下载/二次开发接口，不是主页面内容。
- 工作台固定浅色模式，优先桌面信息密度，同时保证窄屏可阅读。
- 现有 candidate/execution 能力保持可调用；第一版不一次性重排整个代码目录。

## Testing Decisions

- 测试只覆盖公开行为，不验证私有函数、CSS 选择器细节或内部调用次数。
- 研究投影接缝：用独立已知样本验证同步、指标、冻结模型、缺失处理、Variational 过滤和诊断输出。
- HTTP 接缝：验证 Dashboard、油专题、JSON/CSV、404、只读声明和无执行路由。
- 浏览器接缝：验证从 Dashboard 进入油专题、切换价格源/范围/指标、查看执行表和数据健康；检查桌面与窄屏以及控制台错误。
- 现有 `unittest` 的 HTTP 服务器模式和执行引擎 fixtures 作为测试先例。

## Out of Scope

- 真实订单、交易按钮、签名、钱包、API 密钥、仓位或账户资金展示。
- 自动判断策略盈利或输出 Go 信号。
- 把 Brent 与 WTI 当成同一经济对象或使用固定 1:1 关系宣称完全对冲。
- 第一版全市场 Screener、完整 Funding Screener、通用任意两腿 Grapher 和历史纸上交易回放。
- 修改正在由其他 Agent 开发的 `/Users/shiyang/code/monte-fox`。
- 未经验证的实时展期权重、oracle 模式和账户实际费用。
